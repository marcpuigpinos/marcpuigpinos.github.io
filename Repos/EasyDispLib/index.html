EasyDispLib (EDL) Documentation

GitHub Repository

EasyDispLib (EDL) is a lightweight, high-performance C library designed for software-based 2D graphics rendering. It provides a software renderer that operates entirely on the CPU, enabling pixel-perfect graphics manipulation and sprite composition without requiring GPU acceleration. The library is optimized for drawing 2D primitives and sprites onto a pixel framebuffer, with built-in support for alpha blending and PAM (Portable AnyMap) image format export.

Key Features​

  • Software Rendering: Full CPU-based rendering engine for maximum portability.
  • 2D Primitives: Supports lines, filled triangles, rectangles, and circles.
  • Sprite Management: High-level sprite loading (PAM format) and composition.
  • Alpha Blending: Sophisticated alpha compositing for seamless sprite layering.
  • Frame Buffer Control: Direct management of RGBA pixel buffers.
  • Zero External Dependencies: Built using only the standard C library.
  • PAM Export: Quick snapshots of the framebuffer in PAM (P7) format.

Core Data Structures​

The library relies on several fundamental types and structures to manage graphics data.

Primitive Types​

  • edl_u32: A 32-bit unsigned integer used for colors and dimensions.

Vectors​

  • EDL_VEC2: A 2D integer vector.
    • x: The X-coordinate or width.
    • y: The Y-coordinate or height.

Graphics Objects​

  • EDL_SCREEN: Represents the drawing canvas (framebuffer).
    • res_x: Width of the screen in pixels.
    • res_y: Height of the screen in pixels.
    • buffer: Pointer to the 32-bit RGBA pixel buffer.
  • EDL_SPRITE: Represents a graphical sprite.
    • width: Width of the sprite in pixels.
    • height: Height of the sprite in pixels.
    • img: Pointer to the array containing the ARGB pixel data.

Color Management​

Colors in EDL are represented as 32-bit unsigned integers (edl_u32) in ARGB format. Each 8-bit segment represents a color component or the alpha (transparency) layer.

Color Format​

The byte order in memory is A | R | G | B (Alpha in the most significant byte).

ComponentBitsRange
Alpha24-310-255
Red16-230-255
Green8-150-255
Blue0-70-255

Hexadecimal Examples:

  • Red: 0xFFFF0000
  • Green: 0xFF00FF00
  • Blue: 0xFF0000FF
  • Black: 0xFF000000
  • White: 0xFFFFFFFF

Color Conversion and Manipulation​

edl_from_hexa_to_rgba​

Converts a 32-bit hexadecimal color into individual 8-bit components.

  • Input: color (edl_u32)
  • Output: r, g, b, a (unsigned char*)

Example bitmasking for Blue component: blue = color & 0xFF;

Example bitmasking for Alpha component: alpha = (color >> 24) & 0xFF;

edl_from_rgba_to_hexa​

Converts individual 8-bit RGBA components into a single 32-bit hexadecimal color.

  • Input: r, g, b, a (unsigned char)
  • Output: color (edl_u32*)

edl_mix_color​

Performs alpha blending to mix a foreground color with a background color.

  • Input: cf (foreground), cb (background)
  • Output: cp (resulting pixel color)

API Reference​

Return Status​

All functions return an int status code:

  • EDL_SUCCESS (0): The operation completed successfully.
  • EDL_FAILURE (1): The operation failed (e.g., null pointer, allocation error, or I/O failure).

Screen Functions​

FunctionDescription
edl_init_screenAllocates and initializes a framebuffer of specified resolution and color.
edl_dalloc_screenFrees the allocated framebuffer memory.
edl_clear_screenFills the entire screen buffer with a solid color.
edl_take_snapshotWrites the current buffer to a sequentially named PAM file (e.g., output_0000.pam).
edl_write_sprite_on_bufferRenders a sprite onto the screen at a given position with alpha blending and clipping.

Sprite Functions​

FunctionDescription
edl_init_spriteInitializes a sprite structure.
edl_dalloc_spriteFrees the sprite's image memory.
edl_line_spriteGenerates a sprite containing a line between two points.
edl_triangle_spriteGenerates a filled triangle using barycentric coordinates.
edl_square_spriteGenerates a filled rectangle of specified dimensions.
edl_circle_spriteGenerates a filled circle with a specified radius.
edl_load_spriteLoads sprite data from a PAM (P7) file.

Pixel Format & Exporting​

The library uses a 32-bit RGBA packed format. For file I/O, it utilizes the PAM (Portable AnyMap) format, which is highly efficient for raw pixel data.

Supported PAM Header:

P7
WIDTH <w>
HEIGHT <h>
DEPTH 4
MAXVAL 255
TUPLTYPE RGB_ALPHA
ENDHDR
<raw RGBA pixel data>

Implementation Example​

The following example demonstrates initializing a screen, creating a red square, and rendering it onto the screen.

#include "easydisplib.h"

int main() {
    EDL_SCREEN screen;
    EDL_VEC2 res = {800, 600};

    // Initialize a green screen
    if (edl_init_screen(&screen, res, 0xFF008800) != EDL_SUCCESS) {
        return 1;
    }

    // Create a red square sprite
    EDL_SPRITE square;
    edl_init_sprite(&square);
    edl_square_sprite(&square, 50, 50, 0x88FF0000);

    // Draw the sprite onto the screen at position (100, 200)
    EDL_VEC2 pos = {100, 200};
    edl_write_sprite_on_buffer(&screen, &square, pos);

    // Export the frame as a PAM snapshot
    edl_take_snapshot(&screen);

    // Cleanup
    edl_dalloc_sprite(&square);
    edl_dalloc_screen(&screen);

    return 0;
}
